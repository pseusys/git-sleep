# AGENTS.md — orientation for AI coding assistants

Read this first.
It is the map of the project, the facts that are not obvious from the code, and the rules code here is written by.
The full design lives in [`docs/superpowers/specs/2026-09-23-git-sleep-design.md`](docs/superpowers/specs/2026-09-23-git-sleep-design.md); user-facing behaviour is in [`README.md`](README.md).

## What this is

`git-sleep` is a local CLI that merges a set of GitHub pull requests, across any number of repositories, in dependency order:

1. **Load the plan**: a JSON file of PR URLs with `depends_on` edges and per-PR settings, validated with pydantic.
2. **Poll every unblocked PR** once per `poll_interval` (default 60 s), with one GraphQL query per PR for its state, mergeability and checks.
3. **Restart failed GitHub Actions runs**, all of a PR's failed runs in one batch, according to its retry policy.
4. **Merge** a PR once its counted checks pass and GitHub reports it mergeable, then start polling the PRs that depended on it.
5. **Exit** when every PR is merged, failed or skipped.

**Runtime**: Python `>=3.10,<4.0`, managed by Poetry; `poetry install` once, then prefix everything with `poetry run`.
**Working directory** is always the repository root.
**Storage**: none; all state is in memory and rebuilt from GitHub on start.
**Secrets**: the GitHub token comes from `--token`, `$GITHUB_TOKEN` or `$GH_TOKEN`, and is never written anywhere.
No token is available in the development environment so far, so the only live runs have been with a bogus token (a clean 401).

## Commands

| What | Command |
| --- | --- |
| Install (also needed before anything imports `git_sleep`) | `poetry install` |
| Tests | `poetry run pytest` |
| Lint | `poetry run ruff check .` |
| Format | `poetry run ruff format .` (CI runs `--check`) |
| Regenerate the plan JSON schema after changing the file schema in `config.py` | `poetry run git-sleep --schema > plan.schema.json` |
| Lint workflows | `docker run --rm --volume "${PWD}:/repo" --workdir /repo rhysd/actionlint:1.7.12 -color` |
| Run | `poetry run git-sleep <plan.json> [--dry-run] [-v]` |
| Live smoke test without credentials | `poetry run git-sleep examples/plan.json --token bogus` (expect a 401 failure, exit code 1) |

CI runs the commands above and nothing that cannot be run locally:
[`python.yml`](.github/workflows/python.yml) lints and tests on Python 3.10–3.14, with both jobs set up by the [`setup-poetry`](.github/actions/setup-poetry/action.yml) composite action, and [`actions.yml`](.github/workflows/actions.yml) runs actionlint.

## Core mechanics

The decision logic is in `Orchestrator._poll` and is specified step by step in the spec's "Decision on each poll".
These are the invariants a change is most likely to break:

- **A PR moves `BLOCKED → ACTIVE → MERGED | FAILED | SKIPPED`**, and a failed or skipped PR only skips its own dependents; independent PRs carry on.
- **Only counted checks matter**: all of them with `checks: all`, only `required` ones with `checks: required`.
- **Failed runs are restarted together.**
  While any counted check is pending, failures wait; then every failed workflow run is re-run in one batch.
- **The retry budget counts batches per PR per head SHA**, so a new push resets it.
  The attempt is counted before the REST calls, so an API error halfway through a batch cannot restart runs forever.
- **A restarted check keeps showing as failed until GitHub replaces it**, so the IDs of restarted checks are remembered and treated as pending.
  Check IDs are GraphQL node IDs, which change when a job is re-run.
- **A failed check with no workflow run** (another service, a legacy status) cannot be restarted and fails the PR at once.
- **Merges are pinned to the head SHA that was checked**; 405/409 from the merge means "wait and retry", 401/404 anywhere means the PR has failed.
- **Dry run records no restarted check IDs**, so its simulated budget runs out and the run terminates instead of waiting forever.
- **PRs unblocked by a merge are polled in the same tick**, not a poll interval later.

## Gotchas

- **githubkit declares `python <4.0`**, which is why `requires-python` is capped; Poetry refuses to resolve otherwise.
- **githubkit derives the GraphQL endpoint from `base_url`**: `/api/v3` becomes `/api/graphql` for GitHub Enterprise, and a test covers it.
- **A missing repository or PR is a GraphQL error, not an HTTP 404**: githubkit raises `GraphQLFailed` with error type `NOT_FOUND`, which the adapter maps to `GitHubError(404)`.
- **githubkit retries rate limits and 5xx errors by itself, sleeping in between.**
  Tests construct `GitHubClient(..., auto_retry=False)` so an error response fails fast; production also passes `http_cache=False`.
- **`GitHubClient` accepts an httpx `transport`**, which is how the adapter tests run real githubkit code against `httpx.MockTransport` with no network.
- **httpx logs every request at INFO**; the CLI raises its logger to WARNING unless `-v` is given.
- **`from sys import stderr` binds the stream at import time**, so anything that later rebinds `sys.stderr` (pytest's capture, a caller redirecting output) is bypassed.
  Streams are the one exception to the import rule below: use `import sys` and `sys.stderr`.
- **`__version__` is read from package metadata**, so `git_sleep` only imports after `poetry install`.
- **The plan schema is strict**: `true` is not accepted as `1`, and unknown keys are errors; both are deliberate.
  The one extra key allowed is `"$schema"`, which editors use and git-sleep ignores.
- **Write optional fields as `Annotated[X | None, Field(...)] = None`, never `Annotated[X, Field(...)] | None`.**
  In the second form pydantic attaches the `Field` to one member of the union: aliases are silently ignored and descriptions land inside `anyOf` in the JSON schema.
- **The JSON schema is generated from the file-schema models, whose field descriptions are its user-facing documentation.**
  `schema.py` adds only what pydantic cannot express: the bare-list and bare-URL shorthands, the URL pattern (converted from Python to ECMA-262 regex syntax) and removing the `null` that only means "not set".
  After changing a file-schema model, regenerate `plan.schema.json`; `tests/test_schema.py` also checks that the schema and the models accept and reject the same plans.
- **`ruff format` also formats Python code blocks inside markdown** (because `preview = true`), including the spec.
- **CI actions are `actions/checkout@v7`, `actions/setup-python@v7` and `actions/cache@v6`.**
  Poetry caching in `setup-python` v7 was not confirmed, so the composite action caches the in-project `.venv` itself, keyed on the Python version and `poetry.lock`.
- **actionlint only checks workflows, not composite actions**, so `.github/actions/` is only exercised by running CI.

## Development routine

Features go through the superpowers skills: `superpowers:brainstorming` (design, approved section by section), then `superpowers:writing-plans`, then test-first implementation.
Specs are saved in `docs/superpowers/specs/`, plans in `docs/superpowers/plans/`.

- **When the implementation deliberately departs from the spec, update the spec in the same change.**
  The spec is what the next agent trusts about behaviour.
- **Write the tests first and watch them fail**, then implement.
- **Before calling a change done, run the tests and the linters for every language the change touched** (see *Linters* below), and update the README and this file if behaviour or facts changed.
- **Commit and push only when the owner asks.**

## Coding rules

Everything below applies to all code in the repository, tests included, unless a rule says otherwise.
[`ruff.toml`](ruff.toml) enforces what can be linted; where a rule cannot be linted, it says so.

### Everywhere

- **Generate nothing that is not used.**
  No functions, constants, variables or types that nothing calls.
- **Comments describe the code, never how it came to be.**
  No notes about the generation process, no "updated to handle X", no changelog in a docstring.
  History goes in commit messages, reasoning in the spec.
- **One documentation comment per file, per type, per function** in `git_sleep/`, not per line; it says what the thing does and points at the spec for the why.
  In tests, the test name is the documentation; helpers and fakes get a docstring.
  Not linted.
- **No backward-compatibility or migration code**, unless it is explicitly asked for.
  Delete the old path in the same change as the new one.
- **Named constants instead of magic numbers.**
  A literal that appears in a comparison, or twice anywhere, is a constant that has not been named yet.
  Enforced by ruff `PLR2004`, except in `tests/`, where a literal expected value is what a test asserts.
- **Imports at the top of the file, never inline.**
  Import individual names rather than modules, and refer to them directly rather than by a fully-qualified path.
  Placement is enforced by ruff `PLC0415` and `I`; the import style is not linted.
- **Prefer importing over invoking.**
  When one file in this project needs another, import it; do not shell out to it, re-exec it, or read its output.
- **Prefer long lines to broken ones.**
  The ruff line length is 320 as a backstop, not a wrapping target, and `ruff format` joins lines that were only wrapped for width.
  Markdown is the exception: one sentence per line, no hard wrapping.
- **Test code lives in its own tree, mirroring the source tree.**
  `git_sleep/<module>.py` is tested by `tests/test_<module>.py`, and test-only helpers never sit in `git_sleep/`.
- **Do not embed generated content in code.**
  Configuration, fixtures and queries live as separate files (e.g. `status.graphql`), not as string literals inside a program.

### Python

- **Concurrency is written with `async`, not threads**, unless the workload is genuinely CPU-bound.
  The orchestrator is currently a single-threaded polling loop; if it ever polls PRs concurrently, use githubkit's async API.
- **Type hints wherever the language allows them**, tests included.
  Enforced by ruff `ANN` (`Any` is allowed where a library gives nothing better).
- **`from module import name`, not `import module`**, so call sites read as the name and not the path.
  Standard-library imports follow the same rule.
  The one exception is `sys` streams, for the reason in *Gotchas*.
- **Constants at module level, in `UPPER_SNAKE_CASE`**, above the first function.
- **`pathlib.Path` for all filesystem access, never `os.path` or a bare `open()` on a string path.**
  A `Path` composes with `/` and its methods read as operations on the path.
  Enforced by ruff `PTH`.
- **Linted and formatted with `ruff`**, configured in [`ruff.toml`](ruff.toml); CI runs both `ruff check .` and `ruff format --check .`.

### GitHub Actions

- **Run on every branch.**
  A branch filter is how a workflow quietly stops running for whoever needed it most.
- **Scope with `paths` instead.**
  A workflow that cannot fail on a change should not run on it.
  Include the workflow's own file, and any composite action it uses, or edits to them go untested.
- **Declare `concurrency` explicitly**, keyed on the workflow and the ref.
  Cancel superseded runs on side branches; leave the default branch alone, where a cancelled run leaves an uninterpretable gap.
- **`runs-on: ubuntu-latest`** for anything platform-independent.
  Use another runner only where the job genuinely depends on the platform, and say so in the step name.
- **Declare `permissions`**, starting from `contents: read` and adding a scope only when a step needs it.
- **End every step name with a relevant emoji.**
  The log view is a wall of similar names, and the emoji is what makes the failed one findable.
- **A `run:` block holds one short command, with `shell: bash` stated.**
  Anything longer than about three lines goes in `.github/scripts/`, because inline YAML shell cannot be linted, run locally, or tested.
- **Two or three consecutive steps repeated across jobs or workflows become a composite action** in `.github/actions/<name>/action.yml`, used as `./.github/actions/<name>`.
  Copies drift, and the one that drifts is the copy nobody is looking at.
- **Pin actions to a major tag** (`@v7`), which gets security fixes without a bump.
  Pin exactly only where no major tag exists (the actionlint Docker image) or a minor release has broken this project, and say which in a comment.
- **One workflow per language**, each with its own `paths` scope, so a change to one does not wait on a toolchain it cannot affect.
- **Cache whatever is reusable between runs**, keyed on a hash of whatever determines the contents (`hashFiles('poetry.lock')`), so it invalidates itself.
- **Linted with `actionlint`**, configured in [`.github/actionlint.yaml`](.github/actionlint.yaml); it also runs `shellcheck` over every `run:` block.

### House conventions

- **Runtime models are frozen pydantic models**; the file schema uses `extra="forbid"` and `strict=True`.
- **Only `github.py` knows about githubkit.**
  Everything it raises becomes `GitHubError(status, message)`, and the engine depends on the `Client` protocol, not on `GitHubClient`.
- **The engine takes its clock and sleep as parameters**, so tests drive time with a fake clock instead of sleeping.
- **Engine tests use `FakeClient`; adapter tests use `httpx.MockTransport`; nothing in the test suite touches the network.**
- **Logging goes through the `git_sleep` logger**: events (restarts, merges, failures) always at their level, repeated waiting messages at DEBUG.
